# 界面开发

## 响应式 UI

- 开发 Web UI 时使用 Bun + TypeScript，框架选型优先考虑 TanStack 生态。
- Web UI（含 Tauri 的 Web 界面）尽量使用相对单位。字号、间距和组件尺寸优先用 `rem`，随容器变化的尺寸用 `%`，确实随视口变化的尺寸用 `vw`、`vh` 等。移动端需要跟随可见视口高度时优先用 `dvh`，细边框等固定细节可用 `px`。
- 在目标视口宽度、高度和宽高比下检查视觉层级、比例和留白。空间不足时允许换行和重排，确保内容和控件可读、可操作。

## 布局稳定性与响应式重排

- 明确必须保持可见、可操作的关键控件，如主要操作按钮和当前任务所需的输入框。为它们保留内容可读所需的最小尺寸和可用的点击或触控区域，让标题、描述等弹性区域优先让出空间。
- 文案变长时，让文本在分配到的宽度内换行，并检查文件名、链接等连续长字符串。必须单行展示时，允许省略并提供查看全文的方式。状态切换时，若加载指示、错误提示或状态标记会挤动用户正在操作的控件，给同一位置的状态内容留出所需空间，或把提示放到独立区域。
- 新增或移除标签、按钮等元素时，根据剩余空间和操作优先级重排。空间不足时，让组件换行或堆叠，或把次要操作收进「更多」菜单，让关键控件保有最小可用尺寸。
- 在运行中的界面用长文案、实际状态切换和允许的最少及最多元素组合验证，覆盖常用宽度、重排临界点两侧和最窄支持宽度。并排查看状态切换或元素增减前后的截图，再实际操作关键控件，确认内容无重叠、裁切或意外横向溢出，关键控件完整可见、点击或触控区域足够，也能通过该平台支持的键盘操作访问。

## 光学对齐

- 先按网格、组件间距和文字基线排版。实际渲染后，若边界框已经对齐，但形状不对称、笔画分布或字形留白让元素看起来明显偏移，再做光学微调。优先检查圆形按钮里的播放三角形、按钮内的图标与文字，以及并排的不同字号文字。若偏差来自错误的行高、间距或素材里的意外留白，先修正原因。
- 根据可见轮廓和视觉重心，做足以消除偏移感的最小调整。比如右指播放三角形看起来偏左时，可略微右移。可复用的补偿优先放在图标资源或共享组件里，保持外层布局、点击热区和焦点轮廓稳定。
- 在可运行的界面里用实际字体、内容和目标视口截图。使用目标设备的像素比或系统缩放设置，保持应用默认缩放（Web 通常为 100%）。先按界面实际显示尺寸查看整张截图，再查看局部。例如，800 CSS 像素宽的界面以 2× 像素比截图会得到 1600 像素宽的图片，查看时按 800 CSS 像素宽呈现。放大可用于定位原因，最终判断回到实际显示尺寸。
- 在相同视口、缩放、内容和控件状态下截取调整前后的画面，并排比较元素在容器内是否看起来居中、与邻近元素是否对齐。复查受影响的尺寸、断点和状态，确认微调没有引入裁切、间距不一致或状态切换时的跳动。

## 桌面 GUI

- 界面数据更新量和频率较低，且与原生层交互较少时，优先选 Tauri。其 Web UI 使用 Bun + TypeScript，优先考虑 TanStack 生态。
- 对原生界面或交互性能有严格要求时，优先选 GPUI。
