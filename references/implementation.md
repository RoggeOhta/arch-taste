# 代码与测试

## 代码风格

- 保持代码干净简洁。使用直接的控制流，以易读、易维护为准。
- 命名应准确表达语义。变量、函数、类型和模块的名称应反映其含义或职责，同一领域概念使用一致的术语。
- 遵循所用语言的惯用写法（idiomatic code），包括命名、类型建模、错误处理和标准库的使用。
- Rust 中优先用 `struct` 和 `enum` 表达字段和状态。结构已知的数据使用具体类型，只有结构确实动态的数据才考虑使用 `serde_json::Value`。

## 测试

- 保持测试精简，优先覆盖关键行为和已知回归风险。避免重复断言和只绑定内部实现细节的测试。
- 重构后检查受影响的测试。保留仍有效的行为验证，更新或删除已失效的测试。
