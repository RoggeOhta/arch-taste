# 技术选型与架构

## 语言与工具链

- 需要静态类型语言时，优先选 Rust。
- 需要动态运行时的技术栈时，优先选 Bun + TypeScript。
- 必要时可以使用 Python。编写 Python 代码时必须添加类型标注，并使用 `uv` 管理依赖和运行代码。
- 项目可自行选择配置文件格式时，优先使用 TOML。

## 架构原则

- 优先通过组合复用和扩展行为。只有存在明确的子类型关系时才考虑继承。
- 尽量将纯逻辑与副作用分开。将 I/O、外部调用和状态修改放在明确的边界，核心逻辑通过参数接收输入并返回结果。
- 明确各模块的职责、对外接口和依赖方向。模块之间通过明确的接口协作，内部实现由各模块自行管理。
- 围绕当前需求设计。只有现有需求确实需要复用或隔离变化时才引入抽象。
- 避免过度防御性编程。在外部输入进入系统时做必要校验，内部代码依赖类型和模块契约已保证的条件。避免重复校验，尤其是在高频执行路径上。
- 考虑目标操作系统和 CPU 架构的兼容性。将平台专属代码和依赖集中在模块边界，并通过条件编译按目标平台选用对应实现。Rust 使用 `#[cfg(...)]` 和 Cargo 的目标专属依赖配置。
- Rust 项目支持多个 target 时，必须使用同一个 Cargo workspace 管理共享 crate 和各 target 的实现。

## 第三方依赖

- 实现新功能前，先查项目已有依赖和生态中是否有现成的第三方库。评估功能匹配度、维护状况、兼容性和引入成本，有合适的库就优先复用。
