# 项目文档

## 架构文档

- 每个项目必须有一份 `architecture.md`，简要说明系统结构、模块职责和依赖方向。
- 每次变更架构时，必须在同一次变更中更新 `architecture.md` 的相关内容。交付前对照实际实现核对文档，确保两者一致。
- 对影响模块边界、存储或运行方式的关键决策，简要记录当时的约束和选择理由。

## GitHub README

- 使用 GitHub Flavored Markdown。开头应有项目主图（banner）、项目简介和与实际状态对应的 badge。确保图片、徽章和链接在 GitHub 上正常显示或可访问。
- 提供快速上手，说明必要的前置条件、安装或接入步骤，以及一个可运行的最小示例和预期结果。
- 优先提供一段可直接复制给 AI Agent 的接入提示词。写清项目能做什么、接入入口、最小配置和使用示例，以及如何验证接入成功。命令和参数以项目实际支持的用法为准。
